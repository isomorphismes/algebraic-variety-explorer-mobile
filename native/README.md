# SURFER native ray tracer

This directory resumes the numerical ray-tracer translation at the corrected
`PreparedSurface` boundary. It does not replace the Java renderer yet.

Christian Stussak's original jsurf/SURFER renderer remains the oracle. The
numerical path here intentionally preserves the original split between F64
geometry/polynomial/root work and F32 material/color work.

## Implemented slice

`surfer_raytracer.c` currently owns a complete single-threaded prepared-surface
ray path:

1. receive one surface polynomial and its three prepared derivatives as sparse
   F64 terms;
2. specialize the surface to a dense polynomial along a ray;
3. clip the ray to the unit sphere while preserving its original parameter;
4. choose the first visible root, using the linear closed-form path for a
   degree-below-two family and a direct port of SURFER's Descartes subdivision
   path otherwise (`EPSILON = 1e-7`, no square-free conversion);
5. evaluate the prepared gradient at the hit;
6. transform and normalize the normal, choose front/back material, and apply
   SURF-style ambient/diffuse/specular lighting;
7. convert F32 color to Java-compatible ARGB rounding;
8. render the current orthographic yaw/pitch/zoom camera slice.

`surfer_render_orthographic_quality` adds an explicit original sampling path:
`SURFER_AA_OG_1X1` for INTERACTIVE and `SURFER_AA_QUINCUNX` with threshold
`0.3f` for adaptive FINAL. Threshold zero selects original supersampling.
Quincunx traces and reuses the expanded pixel-corner grid, applies the six
binary32 squared-color comparisons, traces a center only when required, then
accumulates the original binary32 weights in their original order. The legacy
single-sample entry and its successful pixel/root bytes remain unchanged.

The explicit quality path follows one full-canvas Stussak `RenderingTask`,
including start-plus-increment and subtract-then-add center coordinates.
Original host-dependent overlapping tile partitioning is not reproduced by
this synchronous numerical entry.

`surfer_render_orthographic_cancellable` adds a borrowed synchronous predicate
to the same quality operation. Long polynomial, Descartes and bisection loops
and individual samples poll it and return `SURFER_CANCELLED`; the predicate
does not change completed floating-point operations. The original synchronous
entries supply no predicate.

The separate `surfer_render_session` owner uses positive session/epoch tokens,
mutex-protected identity/currentness and retained per-epoch atomic booleans.
Beginning a new epoch invalidates old queued work; cancel/release also
invalidate active work without freeing its retained state early. A session
render borrows the copied surface for tracing, stages pixels privately, and
rechecks currentness under its lock before publishing. Its synchronous publisher
callback lets JNI copy the actual result array in that critical section.
UI delivery must check currentness again when its callback executes. This
adds neither native worker scheduling nor original tile/thread parity.

The ray bundle keeps camera, clipping, and surface rays distinct. That is not
ceremony: SURFER uses the same ray parameter in three coordinate spaces, shades
at the camera-space hit, and solves the polynomial in surface space.

## Host acceptance

The CI workflow's `native-status-ick` job qualifies the pinned source-built ICK
host compiler and executes
`examples/autogenerated/native-status/verify.grease`. The host compile stages
are declared in `ci/native-status-toolchain.tsv`; strict floating-point flags
remain `-fno-fast-math -ffp-contract=off`. No generic compiler fallback exists.

The tests cover ray-parameter-preserving sphere clipping, first-root selection,
an exact even-multiplicity tangent root, a miss, the low-degree linear path,
normal orientation, a rendered sphere with foreground/background, and a rotated
sphere silhouette.

The status/validation continuation additionally requires malformed input and
capacity refusals before pixel writes, valid empty polynomials and zero
gradients, every observed allocation fault, candidate-stack and coefficient
size overflow, nonrepresentable finite-input coefficient arithmetic, a valid
all-background frame, and rejection of a compiled blank-on-error mutation.
ASan/UBSan/leak execution and exact successful pixel/root-byte comparison
against the retained base core remain required hosted observations. Source
presence and Grease parsing do not establish those results.

The same qualified ICK job now also requires the unchanged original Java AA
reference and `examples/autogenerated/original-adaptive-aa/verify.grease`.
Fifteen exact F32 blend cases and 682 ambient-only pixels across nine bounded
frames distinguish threshold ties, all six comparisons, weights, accumulation
order, binary32 arithmetic and sample placement. Every observed AA/ray
allocation fault must propagate failure; targeted compiled mutations must be
rejected. These tests use real original roots/rays/AA with simple prepared
surfaces and isolate AA from the remaining lighting/specialization gaps. They
do not qualify the full FINAL preset corpus or general image equivalence.

## Error and ownership contract

Public operations return `SURFER_OK`, `SURFER_MISS`, `SURFER_INVALID_INPUT`,
`SURFER_OUT_OF_MEMORY` or `SURFER_CANCELLED`. Clip/root misses are successful geometric misses;
image success is `SURFER_OK` even when all pixels are background. Ray traces
carry one authoritative status rather than a separate hit boolean. Root and
clip outputs are written only on success. Rendering takes an explicit pixel
capacity, validates inputs before writes, and invalidates the whole frame on
runtime failure; partial output must be discarded. The NativeActivity caller
compares enum values explicitly and returns before window publication on error.

The four polynomial arrays remain caller-owned immutable borrows for each
synchronous core operation. The separate surface store/JNI boundary owns copied
snapshots and worker borrows, as recorded in `prepared-surface-handoff.md`.
The AA operation retains no pixel-corner buffer or prepared-surface pointer
after return and introduces no derivative calculation or worker scheduling.
Allocation faults use a private per-call context; fault-injection controls
exist only in caller-owned test probes, with no global allocator/error state.

## Not parity yet

This is the restored ray-tracing nucleus, not a claim that Java can be removed.
The remaining numerical translation includes:

- exact `XYZ -> XY -> univariate` specialization/evaluation order and Kahan
  collection parity rather than the current direct sparse-to-ray expansion;
- gradient specialization parity rather than direct sparse derivative
  evaluation at the hit;
- the full original FINAL-quality material/lighting/preset corpus beyond the
  bounded original AA observations;
- complete Activity worker concurrency and latest-request delivery through the
  additive cooperative-session contract;
- complete Activity/render ownership through the separate copied-snapshot API;
- the frozen Java semantic/numerical/image oracle corpus required by issue #17.

The old pure-Idris ray tracer remains historical reference work. The maintained
replacement architecture is the typed Idriç semantic front end followed by this
C numerical layer and a thin Android shell.
